## 三、建成的工具（全部可复跑，均支持断点续扫）

| 工具 | 干什么 | 用法 |
|---|---|---|
| `tools/asmrone_collect.py textscan` | 全站拉轨树登记文本节点 | `textscan --workers 24 --out D:/Downloads/asmr-collect-staging` |
| `tools/asmrone_collect.py bsniff` | 纯txt作品内容嗅探（台本/字幕皮/说明） | `bsniff --out 同上` |

| `tools/ingest_gold_pairs.py` | 双语字幕 → 提取配对 → Sakura×人工中文验钞门 | `ingest_gold_pairs.py [--rj N ...] [--report]` |
| `tools/hunt_gold.py`（上轮） | 全池双语作品猎手 | 已收官 |

管线设计要点：双语同轴文件按"同一时间戳日文行+中文行"直接配对；分轴文件走
偏移自校正（时间差 0.25 秒分桶取众数，与不偏移平手取不偏移）+ 1:1 贪心重叠配对；
跨文件按 (时间,日文,中文) 全同去重；轨名被翻译时用轨号匹配兜底。
验钞门=本地 Sakura 翻译日文 vs 人工中文的字符相似度分层（≥0.62 直通 /
0.42~0.62 复核 / <0.42 隔离），全量留痕不丢弃。

## 四、踩过的坑（防再踩，每条都付过学费）

1. **asmr.one 端点**：`/api/search` 的翻页/关键词参数全失效；正解是 `/api/works`
   翻页（pageSize=200 有效）+ `/tracks/{id}?v=2` 拉轨树。
2. **分片并发漂移**：多进程分片必须"先取模定领地、再排除已扫"，反了会跨片重复
   （实测 317 部）。
3. **双语同轴识别**：`parse_srt_vtt` 把一个 cue 的多行拆成同时间戳的多条记录，
   判双语要按时间戳分组，不能假设"一个 cue 一段文本"。
4. **编码**：汉化组字幕有 GBK 系编码——必须"utf-8 严格模式失败再退 gb18030"，
   用 errors=replace 会静默产出乱码（RJ1079813 全部 908 对曾被冤判废）。
5. **轨名被翻译**：同一部作品中日两侧轨名各是各的语言，靠轨号匹配兜底；轨号
   正则最多吃两位数字（"06 4回目"会被读成轨号 064）。
6. **重复提取**：主轨+特典重发、vtt/txt 姊妹副本极常见，必须全同去重。
7. **逐行判语言不可靠**：日文汉字主导的短行长得像中文；readme/台本的 .txt
   会污染"双语"判定。双语判定必须按 cue 成对，单语判定用整文件假名占比。
8. **采样漏语言**：同轨名两种语言会被去重丢掉（RJ1187282 十轨日文+十轨中文
   曾被判"只有日文"）——按字幕所在文件夹分散取样（日中字幕几乎总在不同文件夹）。
9. **429 限流**：24 并发连跑数小时后会被限流；补救=冷却 15 分钟+降到 6 并发补扫；
   断点续扫会把 error 行也当已完成，重扫前必须先剔除 error 行。
10. **Git Bash 调 taskkill 的斜杠转义不可靠**，杀 Windows 进程用 PowerShell
    `Stop-Process -Id ... -Force` 最稳。
