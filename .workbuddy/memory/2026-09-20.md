## 第三轮：调优数据补全 + 挖出一个真 bug

用户问「现在日志数据能当调优数据吗」，结论是**不能，缺四个关键字段**。
按授权只补了缺口 1、2：

### 已实现
1. **`seg-drop` 事件**：`Segmenter._emit` 里被 `MIN_SEG_S` 丢弃的段以前完全不可见。
   现在写 JSONL（`reason/voiced_s/audio_s/t_start/t_end/rms`）。
2. **绝对时间边界**：`Segmenter` 新增 `_total_samples` / `_seg_start_sample` 追踪，
   段以 `(audio16, t_start, t_end)` 三元组入队，`asr`/`mt` 事件都带 `t_start`/`t_end`/`seg_id`。
3. **`seg_id` 关联 ID**：把同一内容的 `asr` 与 `mt` 事件串起来（以前只能靠文本模糊匹配）。
4. **翻译质量标记**：`mt` 事件新增 `zh_empty` / `zh_len`。

### 挖出的真 bug（重要）
补 `voiced_s` 日志时发现：**`MIN_SEG_S=1.5` 门槛一直是失效的**。

- `_emit` 会把 `hang_frames=3` 帧挂起静音一起打包，每段自带 **~1.53s 静音垫**。
- 于是哪怕只有 1 帧人声（0.51s），打包后也是 2.04s，必然越过 1.5s 门槛。
- 实测：**0.4s 爆音 → 入队段长 2.55s，门槛完全没拦住**。
- 这也纠正了之前的一个误读：「<1.5s 碎片从 788 降到 0」不是因为门槛生效，
  而是因为 `hang_s` 0.9→2.0 把它们**合并进邻段**了。

**修法**：新增 `_voiced_frames` 只数真正 voiced 的帧，门槛改判 `voiced_s`；
同时 `_emit` 把尾部挂起静音**剪掉再送 ASR**（省算力，也避免静音把 `avg_logprob` 拉低）。

### 验证
- 单元：0.4s/0.3s 爆音 → 正确 drop；2.5s/4.0s 人声 → 正确入队；剪静音后段长 3.06/4.59s。
- 端到端：真实 `WorkLog` 写出 `seg-drop` 事件，字段完整。
- 真实素材 `smoke_ja.mp3` 回归：识别+翻译仍正确（Sakura 输出正常）。
- 全文件 `py_compile` 通过。

### 遗留
- 缺口 3（翻译拒答/截断标记）、缺口 4 的完整版（`mt` ↔ `result_q` 端到端 ID）未做。
- `logs/` 已 22 个文件且持续增长，缺轮转/清理策略。
- 句重组仍受阻：需要**修正后的规则 + 时间间隔约束**（现在有 `t_start/t_end` 了，可算间隔）。

## 第四轮：按「顺序」推进（真实回放验证 → 拒答检测 → 重组）

### ① 拒答检测（补了缺口 3 的一半）
新增 `REFUSAL_RE` / `is_refusal()`，接在 `mt_loop.translate_one`。
命中则**丢弃不显示**（防止"我是AI我无法…"变成字幕），日志标 `[mt-refusal]`，
`mt` 事件加 `zh_refusal` 字段。

调优过程：初版 `我(不能|无法|没有办法)` 太松，误杀"我无法用语言形容"。
收紧为必须跟拒绝类动词后：10/10 抓取、10/12 放行（2 个边缘误杀可接受）。

**扫 695 条历史真实译文 → 命中 0**。诚实结论：Sakura+ASMR 场景拒答极罕见，
这是"防火"不是"治病"。不过误杀代价远小于漏报代价，保留。

### ② 新增 `--replay`：唯一可信的离线验证手段
之前的 `--source-audio` 是把整个文件当**一段**直接灌进 `seg_q`，
**绕过了 Segmenter** —— 所以拿它验证分段/重组参数是假的。
新增 `--replay`：原速（100ms 一块）喂进真正的 `Segmenter`，产出真实段边界。
另加 `Segmenter.flush()` 让流尾的积压段能吐出来。

配套：
- `logs/make_test_audio.py`：edge-tts 合成 11 句日语，**停顿结构已知**
  （短停 0.4~0.5s 模拟换气，长停 3.0s 模拟句终）
- `regroup.py`：带时间间隔约束的重组规则（独立模块，纯函数）
- `logs/validate_regroup.py`：验证用；**无时间戳日志直接拒绝运行**

### ③ sentence regrouping：验证结果是「不该做」
这是本轮最重要的结论，**推翻了我自己之前的判断**。

用 `test_convo.wav` 原速回放，拿真实段边界对比设计意图：

| 设计 | 期望 | 实测 |
|---|---|---|
| `すごく気持ちいいですよ` +0.4s+ `ね` | 应合并 | **已是同一段** ✅ |
| `うん` +0.4s+ `そうですね、私も…` | 应合并 | **已是同一段** ✅ |
| 长句 +3.0s+ 长句 | 应断开 | 间隔 2.5~3.0s，正确断开 ✅ |

重组规则跑真实数据 → **合并 0 次**，而且这是**正确**结果。

**根因（架构层面）**：`Segmenter` 在音频层已经用 `hang_s=2.0` 做了"按停顿合并"。
<2s 的停顿根本不产生新段，所以段间间隔**恒 >= 2.0s**。于是任何靠间隔判断重组的规则
都只能二选一：
- 阈值 < 2.0 → 永不触发
- 阈值 > 2.0 → 把独立句也并进来（正是旧版错误）

**旧版 regroup 的"压缩 14.9%"是假的**：它在没时间戳的日志上瞎猜，
把间隔 5~10s 的独立句也并了，所以"看起来有效"。

**教训**：`hang_s`（音频层）和"句重组"（文本层）解决的是同一件事。
先确认哪层已经做了，再决定要不要在另一层重复做。

### ④ 缺口 4：判断为不值得补
`mt` ↔ `result_q` 是纯内存直通，无分叉/无重排/无丢弃。之前怀疑的"队列重排"
已用数据推翻（0 次时间戳倒置、队列从未满）。在已证明没问题的链路上加埋点是
给自己制造维护负担。**不做。**

## 第五轮：30 分钟真实环回测试（最重要的发现）

**命令**：`live_sub.py --model anime --mt sakura --layer 2 --duration 1800`
**素材**：系统正在播放的真实日语 ASMR 直播（`耳机 (Senary Audio) [Loopback]`）

### 总数据
- asr 调用 **193** 次 / 字幕 **24** 条 / 丢弃 5 条（low-conf 4 / sound-only 1）
- **空识别 162 次 = 84%**

### 关键发现：`--layer 2` 的 Silero VAD 在 ASMR 场景下是**纯负收益**

**决定性证据**（同一段音频 `probe_now.wav`，测试期间实时抓的 16 秒）：

| layer | 结果 |
|---|---|
| **layer 0**（无 VAD） | ✅ 识别出 `んんぅ…んっ、んんっ、んっ、んんっ…` |
| **layer 2**（Silero VAD） | ❌ **完全无输出** |

**频谱实测**：49.3% 能量 < 300Hz，**300-3000Hz 几乎为零**（语音主频段），
频谱重心 11,993Hz。这是 ASMR 典型的**气声/耳语/呼吸声**，不是正常说话。
Silero VAD 按正常语音训练，对这种内容判定为"没人说话"，整段丢弃。

**历史会话佐证**：layer 2 空识别率 96%，layer 0 是 68-82%。

**结论：ASMR 场景应使用 `--layer 1`（文本过滤，无 VAD），不要用 layer 2。**
`ad_context`：`vad_filter=True` 那套参数是我在第二轮加的，当时以为能省算力，
实际在 ASMR 上是反效果。
